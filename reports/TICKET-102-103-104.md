# TICKET-102, TICKET-103, TICKET-104 — Completed

**Sprint:** Sprint 1 — Backend Foundation (the core sync API — everything else in Sprint 1 was building toward this)

## What was built

**`GET /api/questions/sync?examType=X&since=<timestamp>&page=0&size=500`**

- `examType` is required — 400 with a clear error if missing.
- `since` accepts either `0` (full sync — treated as "since the beginning of time") or an ISO-8601 timestamp (e.g. `2026-01-01T00:00:00Z`) for delta sync. Invalid formats return 400 with a clear error.
- Results are **ordered by `updatedAt` ascending** — this matters for TICKET-304 later (mobile resuming an interrupted sync from the last successfully-processed page): a client can always safely resume from "give me everything after the last `updatedAt` I saw," even mid-pagination.
- `size` defaults to 500 (the agreed page size) and is clamped to a max of 1000 so a client can't request an unbounded page.
- **Soft-deleted questions are included** in results (not filtered out) — this is intentional and essential: the mobile client needs to know a question was deleted so it can remove it locally, which is the whole point of soft-delete + `updated_at` in the schema design from TICKET-101.

## Why TICKET-102/103/104 shipped together

Pagination (103) and testing (104) weren't separable follow-ups here — the endpoint's pagination behavior (page size, ordering) is exactly what the tests needed to verify, and writing the endpoint without immediately testing it would have meant re-verifying it by hand later anyway. Same pattern as TICKET-110.

## Tests (`SyncEndpointTest.java`, 6 tests, all passing)

1. Full sync (`since=0`) returns a freshly created question
2. Delta sync only returns changes after the given cutoff timestamp (verified with a real create-then-create-with-delay sequence)
3. Soft-deleted questions ARE included in sync results, with `deleted: true`
4. Missing `examType` → 400
5. Invalid `since` format → 400
6. Page size is respected (requested 2, got exactly 2 back)

Uses the same `AbstractIntegrationTest` base as TICKET-110 (real Neon dev DB, self-cleaning via direct repository hard-delete).
