# Practice & Mock Test — Navigation Flow + Exit Warning + State Reset

**Closes:** an explicit user spec, un-ticketed. Two requirements: (1) Mock Test's screen flow didn't match Practice's shape — it skipped exam selection and showed a flat list of every mockable paper across every exam as its first screen; (2) no warning existed before a tab switch silently abandoned an in-progress Practice quiz or Mock Test, and Expo Router's tabs preserve each tab's nested-stack state, so returning to that tab could resurface the exact abandoned question.

## What existed before

Confirmed by reading the code directly, not assumed: `mobile/src/app/(tabs)/mock-test/index.tsx` looped every synced exam via `getSyncedExams()`, fetched each one's mockable papers, and flattened the result into one list shown as the module's very first screen — there was no per-exam grouping step at all, unlike Practice's `Exam → Subject → Topic → Level → Quiz` shape. Neither `practice/quiz.tsx` nor `mock-test/test.tsx` had any mechanism to detect "the user is switching modules mid-session" — the only existing exit-confirmation was `mock-test/test.tsx`'s own "Exit without submitting?" button, unrelated to tab switching.

## What was built

**Mock Test flow restructuring.** `mock-test/index.tsx` was replaced with an Exam Selection screen mirroring `practice/index.tsx`'s pattern (search box, one card per synced exam, `getSyncedExams()` refetched on `syncVersion`/`mode` change) — minus Practice's "All Government Exams" shortcut, which has no Mock Test equivalent since a mock paper always belongs to exactly one exam's structure. A new file, `mock-test/papers.tsx`, got the *old* `index.tsx`'s list-rendering logic, narrowed to one exam via `useLocalSearchParams<{ examCode, examLabel }>()` instead of looping every exam. `mock-test/_layout.tsx` gained one new `<Stack.Screen name="papers">` between `index` and `start`. The flow is now `Mock Test tab → Exam Selection → Mock List → Test Details → Test`, matching Practice's shape; `start.tsx`/`test.tsx`/`result.tsx` needed no changes since they already only cared about the params passed to them.

**Shared active-session signal — `mobile/src/practice/activeSessionContext.tsx` (new).** Follows this codebase's existing Context+Provider+hook shape (`sync/SyncContext.tsx`, `practice/authContext.tsx`): `activeSession: "practice" | "mock" | null`, `beginSession(kind)`, `endSession()` (normal completion), `abandonSession()` (cut short — see below), and `resetSignal: { practice, mock }` counters. Mounted in `mobile/src/app/_layout.tsx` as the innermost provider, wrapping `RootNavigator`.

`practice/quiz.tsx` calls `beginSession("practice")` once real questions load, `endSession()` on normal quiz completion (before navigating to the summary screen). `mock-test/test.tsx` does the same with `"mock"`, plus wires the pre-existing "Exit without submitting?" button to `abandonSession()` instead of a bare `endSession()`, so that path also correctly resets state.

**Tab-switch interception — `mobile/src/app/(tabs)/_layout.tsx`.** `<Tabs screenListeners>`'s `tabPress` handler checks whether a session is active and, if so, calls `e.preventDefault()` and shows a native `Alert.alert("Leave this test?", "You are moving to another module. Your current test state may be lost if you leave now.", [Stay, Leave])` — matching the exact copy specified. "Stay" does nothing (dismisses only). "Leave" calls `abandonSession()`.

## Real bugs found and fixed

All four of these were found by actually clicking through the feature on the Android emulator after the first implementation passed `tsc` cleanly — none were visible from reading the code.

1. **`router.dismissAll()`/`dismissTo()` never actually worked, in any calling context tried.** The first implementation called `router.dismissAll()` from the tab bar's Leave handler to reset the abandoned module's stack. This produced a visible red error toast, "The action 'POP_TO_TOP' was not handled by any navigator," and did nothing. Moving the same call to fire from *inside* the affected screen (`test.tsx`/`quiz.tsx`, genuinely nested inside the correct Stack) still produced the identical error. Root cause never fully pinned down beyond "these two APIs are unreliable in this exact expo-router version (57.0.11) regardless of call site" — confirmed by testing both plausible call sites, not assumed from one failure.
2. **A `<Stack key={resetSignal.mock}>` remount looked like a fix but didn't reset anything.** The next attempt bumped a `key` prop on `mock-test/_layout.tsx`'s `<Stack>` to force a full component remount back to its first screen. No error was thrown, but re-opening the Mock Test tab still resumed the exact abandoned test, timer still counting down. Root cause: React Navigation's nested-navigator state is owned by the *parent* Tabs navigator's own state tree, not the child `<Stack>` component — remounting the component just re-subscribes a fresh component instance to the same unchanged parent-owned state. The actual working fix: a plain `router.replace()` to the module's own first route, called from inside the owning screen (the same mechanism `confirmExit` and `submitTest` already used successfully elsewhere in this codebase) — this genuinely mutates the navigation state tree instead of just remounting a component around it.
3. **The Leave action raced itself and stole focus back to the wrong tab.** After fix #2, tapping "Leave" while on Mock Test's Home-tab-bound dialog would briefly land on Home, then instead land back on the Mock Test tab's Exam Selection screen — because the tab bar's `navigation.navigate("index")` (switch to Home) fired synchronously, then an asynchronous `useEffect` inside `test.tsx` (reacting to the just-bumped `resetSignal.mock`) fired its own `router.replace("/mock-test")` moments later on the same shared router, and the second call won. Fixed by removing the tab bar's own navigation call entirely: it now stashes the intended destination in `pendingDestinationRef` (added to the context) *before* calling `abandonSession()`, and the owning screen's effect completes the trip itself, in order — its own `replace()` to reset its stack first, then the stashed destination — so there is only ever one navigation actor per Leave action, not two racing each other.
4. **A stale closure in the tab-press guard.** `screenListeners`'s per-route `tabPress` closures are evaluated once by expo-router's `Tabs`, not fresh on every parent re-render — a check written as `if (!activeSession) return` (reading the value destructured at render time) could see a stale snapshot from whenever that particular route's listener was first created, independent of the real current session state. Fixed by reading a `activeSessionRef` (a ref kept in sync on every `setActiveSession` call) inside the handler instead of the closed-over state value — the same reasoning that makes refs the standard fix for "event handler needs the latest state despite a snapshot-prone closure."

## Verified

Verified end-to-end on the Android emulator, replaying the full flow after each of the four fixes above until all of it worked together correctly in one pass:
- Mock Test tab → Exam Selection (search box, one card per exam) → tapping an exam → that exam's Mock List only (confirmed a second exam, RBI Assistant, correctly showed only its own paper, not SSC CGL's) → Test Details → a live, running test (real question content, countdown timer).
- Mid-test, tapping any other tab shows the "Leave this test?" dialog with the exact specified copy and Stay/Leave buttons.
- **Stay**: dialog dismisses, same question, timer kept counting down from where it was — nothing reset.
- **Leave**: lands on the tab the user actually tapped (confirmed for both Home and Progress as destinations, not just wherever the abandoned module happened to be) — not silently redirected back to the abandoned module.
- Revisiting Mock Test after a Leave shows Exam Selection, not the abandoned test — confirmed with a screenshot showing a *different*, freshly-generated question and a timer reset to near-full, proving it was a genuinely new attempt rather than the same one resuming.
- The identical Stay/Leave/reset behavior confirmed separately for Practice (`Reasoning → General → All Levels` quiz), including landing back on Practice's Exam Selection after Leave.
- Browsing-only check: sitting on a Mock List with no test started, switching tabs shows **no** dialog at all — confirms the guard is scoped to a genuinely active session, not "anywhere inside the module."
- `npx tsc --noEmit` clean after the final version of every changed file.

One verification-methodology note worth recording: several early "it's broken" observations during this testing turned out to be a real Android emulator display-pipeline glitch (a stale cached frame shown by `screencap`, not the app's actual current state) — confirmed by cross-checking against a `uiautomator dump` and by toggling the screen off/on to force a `SurfaceFlinger` refresh, which is the same workaround this project's own history already documents for this exact emulator quirk. Later verification passes used that toggle before every screenshot specifically to rule this out.

## Honest gaps

- Only tab-switch abandonment is guarded. Neither `quiz.tsx`'s native header back-arrow nor `test.tsx`'s Android hardware back button intercepts an in-progress session — pressing either during an active session silently discards it with no warning, exactly as before this feature. This was a deliberate scope decision (the spec described "navigating to another module," which maps to tab switches, not in-module back navigation) rather than an oversight, but it means the feature only partially satisfies a literal reading of "never lose test state unexpectedly."
- After a Leave, the abandoned module's back-stack isn't fully cleared — only its *current* screen is replaced with its first route. E.g. leaving mid-test still leaves `papers`/`start` sitting underneath the fresh `index` screen in the stack; pressing the header back button from a freshly-reset Exam Selection screen would reveal `start` (Test Details), not exit the tab. This is a pre-existing imperfection in the same `router.replace()` pattern `confirmExit` already used before this feature existed, not a new regression — flagged rather than silently accepted.
- The user reported after this work that they "have some issues with latest changes" to discuss later — not yet identified or triaged as of this report.
